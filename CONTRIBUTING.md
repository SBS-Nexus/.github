# Beiträge

Lesen Sie zuerst die Anweisungen des betroffenen Repositories. Begrenzen Sie Änderungen auf ein konkretes Problem und dokumentieren Sie tatsächlich ausgeführte Prüfungen.

- Keine Secrets, Kundendaten, lokalen Datenbanken oder Produktionskonfigurationen einchecken.
- Fehler mit synthetischen Beispielen reproduzieren.
- Sicherheitsmeldungen nach SECURITY.md vertraulich behandeln.
- Produktbehauptungen, Namen und Links anhand aktueller Quellen prüfen.
- Änderungen über einen nachvollziehbaren Branch und Pull Request zur Prüfung bereitstellen.
- Bestehende Lizenz- und Rechtehinweise bleiben maßgeblich. Dieses Repository erteilt keine zusätzliche Lizenz.
